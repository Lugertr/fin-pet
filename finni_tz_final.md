## 4. Локальный профиль и авторизация

### 4.1 Концепция

Приложение работает полностью локально по умолчанию. Профиль = игровое имя питомца + внешний вид. Регистрация и персональные данные не требуются.

### 4.2 Модель профиля

```
LocalProfile {
    id: UUID
    pet_name: String              // 2–15 символов
    pet_type: "robot"|"dragon"|"cat"
    pet_appearance: { body_variant: Int, color_variant: Int, accessory: String? }
    created_at: Timestamp
    is_demo: Boolean = false
}
```

### 4.3 Визуальные комбинации

Минимум 9 (3 типа тела × 3 цвета). Аксессуары расширяют число комбинаций.

### 4.4 Онбординг

```
1. Знакомство (1–2 экрана): цель игры, 3 типа решений — обязательное / желаемое / накопить
2. Выбор питомца: тип тела, цвет, аксессуар (опц.)
3. Имя питомца (2–15 символов)
4. Подтверждение вида
5. Стартовый капитал: 100⭐ (50 кошелёк + 50 накопления), базовая комната
```

Выбор «приоритетной ветки» из ранних черновиков исключён: при 4 ветках (3 обязательные + 1 дополнительная, §9.2) он не даёт значимого выбора.

### 4.5 Сохранение состояния

Данные сохраняются после каждого действия. При закрытии/перезапуске — полное восстановление. Удаление — только из раздела для взрослого (§17). Потеря прогресса не допускается.

### 4.6 Серверная авторизация — вне MVP

```
Флаг: online_auth = false (по умолчанию)
При активации в будущем: гибридная авторизация (device_id + email/пароль), JWT, синхронизация прогресса.
```

## 6. Энергия

### 6.1 Параметры

| Параметр         | Значение                        |

| Базовый максимум | 100⚡                           |
| Бонусы декора    | до +50⚡ к максимуму            |

### 6.2 Расходы энергии

| Действие                   | Стоимость                         |
| -------------------------- | --------------------------------- |
| Уроки (в т.ч. повтор)      | Бесплатно                         |
| Тренажёры (Аркада)         | 10⚡ за игру                      |

| Покупки, открытие подарков | Бесплатно                         |

### 6.3 Формула восстановления

```
current_energy = min(100 + decor_max_bonus,
                      stored_energy + hours_passed × (12.5 + decor_recovery_bonus))
```

### 6.4 Энергия и обязательные расходы

Еда — обязательная категория товаров (§12.2). Без еды энергия не восстанавливается полностью. При энергии < 30⚡ питомец «голодный», подсказка купить еду. Низкая энергия не блокирует уроки, бюджет, покупки, накопления, переход между периодами — только Аркаду и ИИ-помощника.

## 7. Игровой период и планирование бюджета

### 7.1 Концепция периода

Игровой период — завершённый цикл финансовых решений, не привязанный к календарному времени; ребёнок сам завершает период. Все счётчики «N периодов подряд» (стрик §5, удержание накоплений §11.5) считаются в игровых периодах, а не в календарных днях — это позволяет пройти их в демонстрационном режиме без ожидания реального времени.

### 7.2 Структура периода

```
НАЧАЛО: доход периода (+20⭐) + стрик-бонус (если применим) → экран планирования бюджета
ТЕЛО: покупки, уроки, тренажёры, ИИ-помощник, накопления, подарки
ЗАВЕРШЕНИЕ («Завершить период»): план vs факт → обратная связь → пересчёт энергии →
    проверка роста стадии (§8) → переход к следующему периоду
ДЕМО-РЕЖИМ: периоды переключаются мгновенно
```

### 7.3 Планирование бюджета

До начала действий — распределение доступной суммы по 3 направлениям:

| Направление  | Описание              |
| ------------ | --------------------- |
| Обязательное | Еда для питомца       |
| Желаемое     | Игрушки, декор, скины |
| Накопления   | На финансовую цель    |

Правила: сумма ≤ доступный бюджет; остаток виден в реальном времени; план редактируется до подтверждения; после подтверждения — база для сравнения с фактом.

### 7.4 Сравнение плана с фактом

По завершении периода — таблица по каждому направлению (план / факт / разница) и нейтральный текстовый комментарий питомца, без оценки ребёнка.

## 8. Состояние и рост питомца

### 8.1 Состояние

Единственный текущий показатель — энергия (§6), отображается полоской на главном экране. Визуальные реакции по диапазонам: 100% — радость; 50–99% — обычный; 30–49% — усталый, подсказка; 0–29% — «голодный», настойчивая подсказка. Смерти, болезни, травмы нет.

### 8.2 Рост: успешные периоды

Рост стадии зависит от совокупности решений за несколько периодов: обязательные расходы покрыты, факт соответствует плану, регулярность накоплений. Период считается успешным, если на момент завершения: энергия ≥ 30⚡ (обязательное покрыто) И в этот период было хотя бы одно пополнение накоплений (регулярность). План vs факт (§7.4) показывается ребёнку в любом случае, но не входит в формулу роста — точное числовое совпадение плана и факта не требуется.

```
PetProgress {
    successful_periods_count: Int = 0
    current_stage: Int = 1   // 1–5, не уменьшается
}
```

### 8.3 Таблица стадий

| Стадия | Название  | Условие              |
| ------ | --------- | -------------------- |
| 1      | Малыш     | Старт                |
| 2      | Подросток | 1 успешный период    |
| 3      | Взрослый  | 3 успешных периода   |
| 4      | Мудрый    | 5 успешных периодов  |
| 5      | Легенда   | 10 успешных периодов |

При корректном сценарии демонстрации стадия 4 достижима в пределах минимума демо-периодов (5, §20).

### 8.4 Правила роста

Стадия не уменьшается. Продажа предметов инвентаря на неё не влияет. При переходе — анимация и объяснение причины.

## 9. Обучение

### 9.1 Иерархия

```
Ветка → Уровень (2–4) → Урок
Урок: теория (3–5 карточек) → мини-игра (quiz / tinder_swipe) → тест
```

### 9.2 Ветки

| №   | Название                | Статус         | Покрывает                                                               |
| --- | ----------------------- | -------------- | ----------------------------------------------------------------------- |
| 1   | Планирование бюджета    | Обязательная   | Доходы/расходы, обязательное/желаемое, покупки при ограниченном бюджете |
| 2   | Формирование сбережений | Обязательная   | Финансовая цель, регулярное откладывание, оценка решений                |
| 3   | Платежи и покупки       | Обязательная   | Практика покупательских решений                                         |
| 4   | Финансовая безопасность | Дополнительная | Сквозная линия Единой рамки компетенций                                 |

Названия трёх обязательных веток совпадают с формулировкой ТЗ (задания минимум по 3 темам: планирование бюджета; формирование сбережений; платежи и покупки). Компетенция об участии значимого взрослого закрывается разделом для взрослого (§17), а не отдельным уроком.

Пример уровней (иллюстративно, детальный контент — в следующем документе):

- Ветка 1: «Доходы и расходы», «Обязательное и желаемое», «Покупка при ограниченном бюджете»
- Ветка 2: «Зачем откладывать», «Финансовая цель», «Оценка результата»
- Ветка 3: «Как совершить покупку», «Сравнение и выбор»
- Ветка 4: «Осторожно, мошенники», «Личные данные и пароли»

### 9.4 Мини-игры

### 9.5 Итоговый тест

5 вопросов, порог 70% (4/5). Сдал → +50⭐ + модалка распределения (§9.6). Не сдал → повтор без штрафа.

### 9.6 Распределение дохода

После каждого урока: слайдер 0–100% кошелёк/накопления, пресеты «Всё в накопления» / 50/50 / «Всё в кошелёк», дефолт 50/50.

### 9.7 Доступность уроков

Первый урок ветки доступен всегда; далее — после прохождения предыдущего; пройденный — доступен для повтора без награды.

## 11. Накопления и финансовая цель

### 11.1 Параметры

| Параметр               | Значение                                                       |
| ---------------------- | -------------------------------------------------------------- |
| Бонус                  | Фиксированный, небольшой, опциональный — не растёт со временем |
| Начисление             | При взаимодействии, не фоновой задачей                         |
| Влияние на прохождение | Не требуется для обязательного сценария                        |

### 11.2 Цель = предмет из магазина

Цель накоплений — конкретный предмет каталога (§12). Пример: кровать 300⭐, скин 500⭐, ноутбук 500⭐, дерево 400⭐, фон комнаты 200⭐.

### 11.3 Механика цели

Выбор предмета → «Копить на это» → прогресс-бар на главном экране → пополнение по периодам → накоплено ≥ цены → покупка → предмет в инвентаре.

### 11.4 Формула бонуса

```
bonus = floor(current_amount × bonus_rate / 100)
```

`bonus_rate` — фиксированное небольшое значение, не увеличивается со временем, не сбрасывается при снятии. Увеличивается только бонусами предметов-копилок (§12.2). Не является имитацией банковского вклада.

### 11.5 Награды за удержание

| Условие              | Награда                                |
| -------------------- | -------------------------------------- |
| 3 периода без снятия | Подарок, гарантированный выбор (§14.1) |
| Достижение цели      | Подарок + 10% цены предмета в ⭐       |

### 11.6 Модель данных

```
Savings { id, current_amount: Int = 0, bonus_rate: Float, target_item_id: Int?, periods_since_withdrawal: Int = 0 }
SavingsTransaction { id, operation_type: "deposit"|"withdraw"|"bonus"|"reward", amount, balance_after, period_id, created_at }
```

## 16. ИИ-помощник

### 16.1 Архитектура

Небольшая локальная ИИ-модель, работающая полностью на устройстве (on-device inference). Интернет и сервер не требуются для ответа. Датасет: ≈1000 пар вопрос–ответ по финансовой грамотности + база знаний, соответствующая содержанию веток обучения (§9). Конкретная реализация (дообученная компактная модель / retrieval по датасету / классификация intent) — на усмотрение команды при соблюдении §16.3.

### 16.2 Параметры

| Параметр        | Значение                          |
| --------------- | --------------------------------- |
| Стоимость       | 5⚡ (до 2⚡ с предметом «облако») |
| История         | Хранится вся, локально            |
| Очистка истории | Доступна пользователю             |
| Сеть            | Не требуется                      |

### 16.3 Обоснование применения ИИ

- Задача: ответы ребёнку на вопросы по темам веток обучения; питомец озвучивает ответ.
- Данные: только закрытый датасет (≈1000 Q&A + база знаний); персональные данные пользователя не обрабатываются и не покидают устройство.
- Контроль корректности: закрытая предметная область (содержание веток §9), датасет курируется командой вручную, свободная генерация вне заданной темы не предусмотрена.

### 16.4 Поведение вне темы

Нераспознанный или внетематический вопрос → нейтральный ответ-заглушка со ссылкой на соответствующий урок, без выдумывания фактов.

### 16.5 Модель данных

```
AiChatMessage { id, role: "user"|"assistant", content, energy_spent, created_at }
```

## 17. Раздел для взрослого

### 17.1 Вход

Барьер: арифметический пример (например, 7×3=?) или удержание кнопки 3 секунды.

### 17.2 Содержимое

| Раздел           | Описание                                   |
| ---------------- | ------------------------------------------ |
| Цели приложения  | Образовательные результаты                 |
| Пройденные темы  | Выполненные задания                        |

| Сброс профиля    | Кнопка сброса к исходному состоянию        |

| Демо-режим       | Активация/сброс демонстрационного режима   |

### 17.3 Правила

Без негативных оценок ребёнка; только позитивная/нейтральная подача; удаление — с подтверждением.

## 21. Обратная связь и последствия

### 21.1 После каждого действия

Отображаются изменения баланса, накоплений, энергии питомца.

### 21.2 При неудачном решении

Понятное объяснение последствия; способ исправить ситуацию; прогресс не обнуляется.

### 21.3 Пути восстановления

| Не куплена еда         | Пройти задание → заработать → купить еду             |

## 4. Локальный профиль и авторизация

### 4.1 Концепция

Приложение работает полностью локально по умолчанию. Профиль = игровое имя питомца + внешний вид. Регистрация и персональные данные не требуются.

### 4.2 Модель профиля

```
LocalProfile {
    id: UUID
    pet_name: String              // 2–15 символов
    pet_type: "robot"|"bear"|"cat"
    pet_appearance: { color_variant: Int }   // 0 — встроенный вид, 1–2 — скины
    created_at: Timestamp
    is_demo: Boolean = false
}
```

### 4.3 Визуальные комбинации

Минимум 9 (3 типа × 3 цвета). **⚠ Сейчас 7:** у робота и кота по 3 вида (базовый + 2 скина), у мишки — только базовый (нет арта и товаров-скинов для вариантов 1–2). См. §30.

### 4.4 Онбординг

```
1. Знакомство: цель игры
2. Три типа решений — нужное / желаемое / отложить
3. Выбор питомца: робот, мишка, кот
4. Облик (любой из трёх: классический или один из двух цветных) и имя питомца (2–15 символов); два других облика придут на уровнях 2 и 3
5. Стартовый капитал: 100 монет (50 кошелёк + 50 накопления), базовая комната
```

Выбор компетенции на онбординге исключён: ветка обучения выбирается заново в начале каждой смены (§7).

### 4.5 Сохранение состояния

Данные сохраняются после каждого действия. При закрытии/перезапуске — полное восстановление, включая идущую смену (её 24 часа тикают и при закрытом приложении) и место в начатом уроке (§9.7). Удаление — только из раздела для взрослого (§17). Потеря прогресса не допускается. Профиль загружается до показа любого экрана — и при открытии прямой ссылкой (веб); без профиля любой экран, кроме онбординга, ведёт на онбординг.

### 4.6 Серверная авторизация — вне MVP

```
Флаг: online_auth = false (по умолчанию)
При активации в будущем: гибридная авторизация (device_id + email/пароль), JWT, синхронизация прогресса.
```

## 6. Энергия

### 6.1 Параметры

| Параметр         | Значение                                        |
| ---------------- | ----------------------------------------------- |
| Базовый максимум | 100⚡                                           |
| Бонусы           | Кровать: +15…+25⚡ к максимуму                  |
| Восстановление   | +12,5⚡/час (полное за 8 часов)                 |
| Отображение      | Число ⚡ в общей шапке на всех экранах           |

### 6.2 Расходы энергии

| Действие                   | Стоимость                                                                      |
| -------------------------- | ------------------------------------------------------------------------------ |
| Уроки (в т.ч. повтор)      | Бесплатно; только в уроке смены (§7.5) неверный ответ — 5⚡                     |
| Тренажёры (Аркада)         | 10⚡ за игру                                                                    |
| ИИ-помощник                | 5⚡ (до 2⚡ с предметом «облако» — таких товаров пока нет, §12.2)                |
| Покупки, открытие подарков | Бесплатно                                                                      |

Штраф за неверный ответ в уроке смены — единственное согласованное отступление от общего правила «ошибка не наказывается» (§2); вне смены и при повторе урока штраф не действует.

### 6.3 Формула восстановления

```
current_energy = min(100 + decor_max_bonus,
                      stored_energy + hours_passed × (12.5 + decor_recovery_bonus))
```

### 6.4 Энергия и обязательные расходы

Еда — обязательная категория товаров (§12.2) и вынужденная мера: купить и съесть её можно, только когда питомец голоден (энергия < 30⚡); сытому питомцу — объяснение, что энергия восстанавливается сама. Цена еды — не ниже 10 монет за 1⚡ (+5…+25⚡), поэтому «еда → энергия → Аркада» не приносит выгоды (Аркада даёт максимум 2 монеты за 1⚡). Низкая энергия не блокирует уроки, бюджет, покупки, накопления, переход между сменами (§7) — только Аркаду и ИИ-помощника (с объяснением «покорми питомца или подожди»). **⚠** Отдельной подсказки на главном экране «питомец голоден — купи еду» нет — см. §30.

## 7. Работа: обучение и планирование бюджета

### 7.1 Концепция

«Работа» (смена; в коде — adventure) объединяет планирование бюджета и прохождение урока в один цикл. Она заменила «игровой период», а затем «Приключение» с 8-часовым таймером, заданиями и событиями по времени (решение команды 28.09.2026). Одна смена — один урок: следующий непройденный урок выбранной темы (компетенции, §9.2). Смена начинается кнопкой «Начать работу» на хабе или тапом по ноутбуку в комнате («Продолжить планирование», если план ещё не подтверждён).

Хаб остаётся хабом и во время смены; экран «Работа» — отдельный, открывается кнопкой «Продолжить работу» (с оставшимся временем) или тапом по ноутбуку. В шапке слева — «назад» на хаб и заголовок «Работа», справа — «?», ✕ (закончить смену раньше), монеты и энергия. Итоги завершённой смены показываются на хабе.

### 7.2 Структура смены

```
ПЛАНИРОВАНИЕ («Смена №N»):
  1. Бюджет работы (100 C) делится на «Потратить» и «Коплю» (§7.3, ⚠ §30 п. 9)
  2. Выбор темы: карточка темы показывает урок, по которому пройдёт смена
     («Урок: …» или «Продолжить: …»); тема с начатым уроком выбрана сразу,
     пройденную целиком тему выбрать нельзя. Смена — это новый урок, поэтому
     после всех 19 уроков новых смен нет (решение 28.09): «Начать работу»,
     ноутбук и «Новая работа» объясняют это — дальше звёзды за повторы и Аркада
  3. «Начать работу» → доход становится бюджетом работы (не кошельком хаба),
     урок смены фиксируется, смена длится до 24 часов
АКТИВНАЯ ФАЗА (до 24 реальных часов; тикают и при закрытом приложении):
  - Экран (макет «Работа»): сцена с питомцем; плашка «Работа: 2 из 5» и трек
    этапов урока — пройденные с галочкой, текущий цветной с иконкой типа
    (тест, мини-игра, событие), будущие серые, последний — завершение урока;
    время до конца смены; карточка текущего шага и «Начать задание» — урок
    продолжается с того же места; карточка «Бюджет работы» (§7.4)
  - Пройденный этап на треке открывается: перечитать карточки, перепройти тест
    или мини-игру
  - События — внутри урока (§7.6): тратят или пополняют бюджет работы
  - Монеты и опыт за урок — сразу при его завершении, в кошелёк хаба (§9.3)
  - Магазин и «Банк» — контур хаба: бюджет и факт смены не меняют
ЗАВЕРШЕНИЕ:
  - Урок пройден — смена заканчивается сама, выплата полная
  - 24 часа вышли — смена заканчивается сама (при запуске приложения, на хабе
    или на экране работы); урок продолжится в следующую смену с того же этапа
  - ✕ — раньше, с подтверждением (в нём — какая доля урока пройдена)
  - Урок не пройден — выплачивается пройденная доля урока (этапы трека вместе
    с финальным: 2 из 4 — половина) бюджета и бонуса за план, без бонуса банка;
    это не штраф, а выбор ребёнка, и «начал смену и дождался конца» не
    приносит весь бюджет
  - план vs факт (§7.4) → бонус за план в бюджет (§5) → выплата: «коплю» — в
    банк, остальное — в кошелёк → итоги полноэкранным окном на хабе →
    «Новая работа» (сразу планирование) или «Домой»
ДЕМО-РЕЖИМ (§18): смену можно закончить ✕ в любой момент с полной выплатой
```

### 7.3 Планирование бюджета

До начала смены — распределение бюджета работы (100 монет) на две категории (решение 27.09, подтверждено 28.09). В каждом поле заливка и подпись «N%» показывают долю бюджета:

| Категория | Описание                    |
| --------- | --------------------------- |
| Потратить | Траты в событиях урока — и на нужное («надо»), и на желаемое («хочу») |
| Коплю     | В конце смены уходит в банк хаба — на финансовую цель |

**⚠** «Надо» и «Хочу» не планируются отдельно — они видны в факте трат (каждый платный вариант события помечен нужным или желаемым). См. §30 п. 9.

Правила: сумма ≤ бюджет работы; нераспределённый остаток виден в реальном времени; план редактируется до подтверждения; после подтверждения — база для сравнения с фактом, доход становится бюджетом работы.

### 7.4 Сравнение плана с фактом

Во время смены — карточка «Бюджет работы» на экране работы: «Нужно» и «Хочу» — факт трат по корзинам, «Коплю» — сколько отложено из плана, подпись «Потрачено X из Y C по плану». Тап открывает окно «План»: бюджет работы, «Потратить» — потрачено из запланированного (из них на нужное / желаемое), «Коплю» — сколько уйдёт в банк. Карточки «Банк» в смене нет — банк открывается только на хабе (копилка).

По завершении — итоги («Итоги работы»): «Отличная работа!» или нейтральное «Смена завершена», если потрачено больше плана; «Потратить» — план и факт (с разбивкой на нужное и желаемое), «Коплю» — план и сколько ушло в банк; перенос в копилку (на хотения и на цель, бонус копилки), бонус за план; если урок не закончен — с какого этапа он продолжится. Опыт и новый уровень показывает экран награды урока (§8.4). Если потрачено больше плана, в банк уходит то, что осталось. Итоги хранятся к смене, пока окно не закрыто, — если закрыть приложение сразу после урока смены, хаб покажет их после перезапуска (§4.5). **⚠** Колонки «разница» и нейтрального комментария питомца нет — см. §30.

### 7.5 Урок смены

Урок смены — следующий непройденный урок выбранной темы (§9), он же «задание». Он проходится этапами (§9.1) с экрана работы («Начать задание»); уйти можно в любой момент — пройденные этапы сохраняются. В уроке смены:

- монеты за урок +10% (§9.3), вместе с процентом ноутбука; опыт — как за любой урок (§8.2);
- события урока платит бюджет работы (§7.6);
- неверный ответ в тесте или мини-игре стоит 5⚡ (§6.2);
- урок пройден — смена завершается.

Повтор уже пройденного урока уроком смены не считается (§9.7).

### 7.6 События в уроке

Событие — действие этапа урока (контент — в `content/lessons.json`, §25): у действия пул событий, выпадает одно, и выпавшее запоминается — после перезапуска то же. Событие связано с ситуацией урока, у него 2–3 варианта: потратить на нужное (`mandatory`) или на желаемое (`optional`), пополнить бюджет (заработок) или ничего не тратить. Правила (проверяются тестом контента): суммы целые, трата — с корзиной, в каждом событии есть бесплатный вариант, двух событий подряд в уроке нет.

В уроке смены деньги события — бюджет работы (он показан на экране события). Трата никогда не уводит его в минус: платный вариант, на который не хватает, недоступен с подписью «Не хватает N монет» (§12.3). Вне смены (повтор урока, демо-урок без смены) выбор ничего не стоит. Решённое событие повторно не меняется. Событий по времени больше нет (решение 28.09).

## 8. Состояние и рост питомца

### 8.1 Состояние

Единственный текущий показатель — энергия (§6), показывается числом ⚡ в общей шапке (отдельная полоска на главном экране убрана как дублирующая). Визуальные состояния питомца: обычный (энергия > 20) и спящий (≤ 20). **⚠** ТЗ предусматривает 4 диапазона (радость / обычный / усталый / голодный) — сейчас их 2, см. §30. Смерти, болезни, травмы нет.

### 8.2 Рост: уровень и опыт игрока

Рост измеряется опытом игрока. Опыт дают уроки — за первое прохождение (решение 28.09): у каждой темы 300 опыта, они делятся поровну между её уроками (3 урока — по 100; не делится нацело — остаток первым урокам). Смена опыта не даёт.

| Источник опыта           | Опыт                                   |
| ------------------------ | -------------------------------------- |
| Первое прохождение урока | 300 ÷ уроков в теме (тема целиком — 300) |
| Повтор, звезда, смена    | 0                                      |

```
PlayerLevel {
    total_xp: Int = 0
    level: Int = 1   // не уменьшается
}
```

На каждый уровень — ровно 300 опыта (`xp_for_level = 300`), поэтому пройденная целиком тема всегда даёт новый уровень. В демо-режиме каждый урок даёт 300 опыта — новый уровень (§18.2).

Прежняя шкала (порог 250 × уровень, опыт за приключение) сменилась 28.09: накопленный опыт пересчитан в новую с тем же уровнем и той же долей пути до следующего (миграция v11) — уровень не понижается. Уроки, пройденные до перехода, опыта задним числом не дают (решение команды 28.09: иначе у существующих профилей сразу вырос бы уровень); звезду за них можно получить перепрохождением.

## 9. Обучение

### 9.1 Иерархия

```
Ветка → Урок → Этапы (точки трека смены) → Заключение
Урок: ситуация → этап 1: карточки → тест или мини-игра → событие
               → этапы 2…n: карточки → тесты, мини-игры, события в любом составе
               → финальный этап: заключение → награда
```

Урок начинается с ситуации — истории про деньги, которая может случиться с ребёнком. Каждый этап начинается с блока чтения (ситуация, карточки теории) — его можно перечитать, затем действия по порядку; двух событий подряд нет. Каждый этап — точка трека смены («Работа: 2 из 5»), последняя — завершение урока с заключением. Пройденные этапы сохраняются сразу — урок продолжается с того же места, в том числе в следующую смену. Правила состава проверяет тест контента (`LessonPlan.validateNodeLesson`). Сейчас все 19 уроков — по 3 этапа (⚠ §30 п. 12).

### 9.2 Ветки

Требование ТЗ Департамента — задания минимум по 3 темам: планирование бюджета; формирование сбережений; платежи и покупки (+ дополнительная «Финансовая безопасность»). Компетенция об участии значимого взрослого закрывается разделом для взрослого (§17), а не отдельным уроком.

Текущий контент: 7 веток, 19 уроков для 7–11 лет; обязательные темы — первыми. Короткие названия веток — для вкладок и матрицы компетенций, тема ТЗ — в описании ветки.

| ------- | ------------ | ----------------------------------------------- | ----- |
| 1       | Бюджет       | Планирование бюджета (обязательная)             | Что такое бюджет? · Нужное и желаемое · Когда монет немного |

### 9.3 Награды за урок

Вариант B (решение 28.09):

| Что                                                    | Награда                                   | Сколько раз |
| ------------------------------------------------------ | ----------------------------------------- | ----------- |
| Первое прохождение урока                               | 60–85 монет (теория 10 + мини-игра 25, если есть, + тест 50) и опыт (§8.2) | один раз |
| Урок без ошибок: все тесты и мини-игры хоть раз пройдены без ошибок | звезда ★ и бонус 25 монет (подтверждено 28.09) | один раз — сразу или при перепрохождении |
| Повтор без новой звезды                                | —                                         | —           |

Монеты — сразу в кошелёк хаба, и за обычный урок, и за урок смены. Ноутбук увеличивает монеты урока на свой процент (§12.2), урок смены — ещё на 10%; суммы округляются до целых. События в счёт «без ошибок» не идут. Награду начисляет одно место — завершение урока; экран награды показывает монеты, опыт, звезду (или как её получить) и новый уровень. Звёзды видны на вкладке «Уроки» — на дорожке и в карточке темы. Энергии уроки не стоят (кроме 5⚡ за ошибку в уроке смены, §6.2).

### 9.4 Мини-игры

| Тип          | Механика                   | Вопросов |
| ------------ | -------------------------- | -------- |
| quiz         | Выбор из 3–4 вариантов     | по уроку |
| tinder_swipe | Свайп влево/вправо         | по уроку |
| five_letters | Угадать слово из 5 букв    | 1 слово  |

Мини-игра — действие этапа урока (§9.1). Жизней нет; ошибка — свободный повтор, без штрафа. Исключение: в уроке смены (§7.5) неверный ответ дополнительно тратит 5⚡ энергии (§6.2). «Свайпы» — вопрос «да / нет»: вправо / ✓ — «да», влево / ✗ — «нет», под кнопками — что значит каждый ответ; стороны постоянные и не выдают верный ответ (решение 28.09; раньше ✓ стояла на верном варианте), верно ли — видно после свайпа; у свайпа свой звук. Порядок вариантов в контенте — `[нет, да]`, проверяется тестом.

### 9.5 Тесты

Тест — действие этапа, сейчас 2–3 вопроса; порог — 70% верных (при 2–3 вопросах — все ответы верно). Сдал — урок идёт дальше; не сдал — повтор без штрафа (кроме 5⚡ за ошибку в уроке смены). Тест и мини-игру можно перепройти и после завершения урока — засчитывается лучшая попытка (для звезды).

### 9.6 Распределение дохода

Отдельного распределения после каждого урока нет: награда за урок зачисляется в кошелёк хаба, а распределение дохода на надо / хочу / коплю происходит при планировании смены (§7.3); в хабе — пополнением «Банка» (§11).

### 9.7 Доступность уроков

- Новые уроки проходятся в смене — по порядку внутри выбранной темы (кнопка «Начать задание» на экране работы). Начатый урок продолжается с того же этапа, в том числе в следующую смену.
- Пройденный урок открывается обзором: перечитать ситуацию и карточки, перепройти тесты и мини-игры (первый раз без ошибок — звезда и бонус, §9.3, иначе без награды) — с вкладки «Уроки» или по ссылке ИИ-помощника. Пройденный этап на треке смены открывается так же.
- В демо-режиме любой урок открывается сразу и проходится в укороченном виде (§18.2).
- Попытка открыть новый урок вне этих правил — объяснение, где его пройти (для начатого — что он продолжится в смене).
- Вкладка «Уроки» показывает состояние урока: ★ — пройден без ошибок, ✓ — пройден, «Начат · N/M» со значком «play» — начат, продолжится в смене, «Следующий» — с него начнётся смена по этой теме, замок — дальше по порядку; в карточке темы — пройдено и звёзды.
- Прогресс урока хранится по номерам «этап.действие» вместе с отпечатком структуры урока (типы действий по этапам). Правка текстов его не трогает; если в контенте поменялся состав этапов, начатый урок начинается заново — завершение, звезда, монеты и опыт сохраняются.

## 11. Накопления и финансовая цель

### 11.1 Параметры

| Параметр               | Значение                                                       |
| ---------------------- | -------------------------------------------------------------- |
| Бонус                  | Фиксированный, небольшой (база 1%), не растёт со временем      |
| Начисление             | При пополнении, не фоновой задачей                             |
| Влияние на прохождение | Не требуется для обязательного сценария                        |

### 11.2 Цель = улучшение ключевой вещи

Цель накоплений — улучшение одной из трёх вещей с бонусами: ноутбука, копилки или кровати (§12.2). Первую цель ребёнок выбирает в онбординге (ближайшее улучшение каждой из трёх вещей), сменить её можно в «Копилке» теми же карточками.

### 11.3 Механика цели

Выбор предмета → «Копить на это» → прогресс-бар во вкладке «Копилка» (туда же ведёт копилка в комнате) → пополнения (из кошелька и «коплю» из каждой завершённой смены) → накоплено ≥ цены → покупка → предмет в инвентаре.

### 11.4 Формула бонуса

```
returned  = min(deposit, withdrawal_credit)   // возврат ранее снятого
new_money = deposit − returned
bonus     = floor(new_money × bonus_rate / 100)
```

Бонус начисляется только за новые деньги: пополнение сначала «гасит» ранее снятое из банка (withdrawal_credit), на возврат своих же монет бонус не начисляется; «коплю» из смены — новые деньги целиком. Поэтому ни пополнения по 1 монете, ни «снял — положил обратно» дохода не дают. `bonus_rate` — фиксированное небольшое значение (1%), не увеличивается со временем. Увеличивается только бонусами предметов-копилок (+2…+4, §12.2). Не является имитацией банковского вклада.

### 11.5 Награды за удержание

| Условие                          | Награда                                 |
| -------------------------------- | --------------------------------------- |
| Достижение цели                  | Предмет цели + 10% его цены монетами    |

Подарков за банк нет — подарок дают только за 7 дней подряд (§14).

```

SavingsTransaction { id, operation_type: "deposit"|"withdraw"|"bonus"|"reward", amount, balance_after, period_id, created_at }

### 12.2 Категории

| Категория                          | Тип расхода    | Эффект                                       |
| ---------------------------------- | -------------- | -------------------------------------------- |
| Еда                                | Обязательное   | Мгновенная энергия (+5…+25⚡); только голодному питомцу, 10 монет за 1⚡ (§6.4) |
| Ноутбуки (ключевой предмет)        | Необязательное | +10…+18% монет за уроки                      |
| Копилки (ключевой предмет)         | Необязательное | +2…+4 к bonus_rate (§11.4)                   |
| Кровать (ключевой предмет)         | Необязательное | +15…+25⚡ к максимуму энергии                |
| Ковёр, окно, фон комнаты           | Необязательное | Только внешний вид                           |
| Декор (в т.ч. скрытые трофеи)      | Необязательное | Только внешний вид                           |
| Предметы ИИ («облако»)             | Необязательное | −⚡ за вопрос ИИ (§6.2) — расчёт реализован, товаров нет |
| Уют, освещение                     | Необязательное | +скорость восстановления энергии — расчёт реализован, товаров нет |

Игровой бонус дают исключительно 3 ключевых предмета — ноутбук, кровать, копилка. В каталоге 28 позиций (4 — еда, 24 — необязательные).

Цены мебели, декора и фона комнаты — в 5 раз выше прежних (750–2250 монет): улучшение не купить на деньги даже одной идеальной смены, на него копят в банке (проверяется автотестом `Economy.test.ts`). Еда не дорожала.

Скины в магазине не продаются и не выпадают в событиях и подарках: облик питомца выдаётся только на новом уровне (§8.3). Целью в банке (§11) можно выбрать только вещь, которая продаётся в магазине.

В магазине, инвентаре и цели банка показывается настоящая картинка вещи (арт мебели и фона комнаты, облик питомца); у еды и скрытых трофеев арта нет — эмодзи.

### 12.3 Покупка

Перед покупкой: цена, категория, влияние на питомца. Требует подтверждения. Отрицательный баланс не допускается; при нехватке — объяснение («не хватает N монет») и вариант действия («К работе» — заработать). Магазин — контур хаба: покупки во время смены её бюджет и факт не меняют.

### 12.4 Продажа

| Тип                       | Продать | Возврат  |
| ------------------------- | ------- | -------- |
| Базовые (стартовые)       | Нет     | —        |
| Купленный декор/мебель/еда | Да     | 50% цены |
| Скины (облик за уровень)  | Нет     | —        |
| Скрытые предметы (§14)    | Нет     | —        |

При продаже размещённой мебели комната возвращается к стартовому предмету категории.

### 12.5 Модель данных

Item { id, name, category, price, expense_type: "mandatory"|"optional",
       energy_restore: Int = 0, energy_max_bonus: Int = 0, energy_recovery_bonus: Float = 0,
       coin_bonus_percent: Float = 0, savings_bonus_rate: Float = 0, ai_cost_reduction: Int = 0,
       is_hidden: Bool = false, rarity: "common"|"rare"|"epic"|"legendary"?,
       pet_type?, skin_variant? }   // скины — 2 на вид (робот, кот)
Inventory { item_id → quantity }, размещение мебели и декора — в сторе магазина
```

## 16. ИИ-помощник

### 16.1 Архитектура

Целевая архитектура — небольшая локальная ИИ-модель, работающая полностью на устройстве (on-device inference): интернет и сервер не требуются. Датасет: ≈1000 пар вопрос–ответ по финансовой грамотности + база знаний, соответствующая содержанию веток обучения (§9). Конкретная реализация — на усмотрение команды при соблюдении §16.3.

**Текущее состояние:** ответ даёт локальная заглушка `StubAiAssistant` (фиксированные ответы по ключевым темам из `content/ai_stub_responses.json` со ссылкой на урок) за интерфейсом `AiAssistant` — модель подменяется без переработки экрана. Списание энергии, история, очистка истории работают по-настоящему. Ссылка на урок подчиняется правилам доступа §9.7.

### 16.2 Параметры

| Параметр        | Значение                          |
| --------------- | --------------------------------- |
| Стоимость       | 5⚡ (до 2⚡ с предметом «облако») |
| История         | Хранится вся, локально            |
| Очистка истории | Доступна пользователю             |
| Сеть            | Не требуется                      |

### 16.3 Обоснование применения ИИ

- Задача: ответы ребёнку на вопросы по темам веток обучения; питомец озвучивает ответ.
- Данные: только закрытый датасет (≈1000 Q&A + база знаний); персональные данные пользователя не обрабатываются и не покидают устройство.
- Контроль корректности: закрытая предметная область (содержание веток §9), датасет курируется командой вручную, свободная генерация вне заданной темы не предусмотрена.

### 16.4 Поведение вне темы

Нераспознанный или внетематический вопрос → нейтральный ответ-заглушка со ссылкой на вкладку «Уроки», без выдумывания фактов.

### 16.5 Модель данных

```
AiChatMessage { id, role: "user"|"assistant", content, energy_spent, created_at }
```

## 18. Демо-режим

### 18.1 Назначение

Режим для экспертной проверки: обязательный сценарий (§19) проходится подряд без ожидания реального времени.

### 18.2 Требования

Цель (решение команды 28.09): весь функционал — от онбординга до повышения уровня — показывается за 1–2 минуты. Все ускорения действуют только в демо-профиле; обычная игра не меняется.

| Требование       | Реализация                                                                   |
| ---------------- | ---------------------------------------------------------------------------- |
| Тестовый профиль | Демо-профиль создаётся в онбординге или включением режима в разделе для взрослого (тогда профиль сбрасывается к исходному состоянию) |
| Смены            | Завершаются в любой момент (✕) с полной выплатой |
| Уроки            | Любой урок открывается сразу; урок укороченный — первые 2 этапа, по 1 карточке, тесты по 2 вопроса; мини-игры и события — целиком (правило §12.3 действует). Каждый пройденный урок — 300 опыта, новый уровень (и облик на уровнях 2–3) |
| Аркада           | Короткие раунды: «Викторина» — 3 вопроса, «Свайпы» — 3 карточки, «5 букв» — 1 слово |
| Сброс            | «Начать демо заново» — демо-профиль удаляется, онбординг открывается с уже включённым режимом |

### 18.3 Активация

Переключатель «Режим демонстрации» на первом экране онбординга (⚠ §30 п. 8) или переключатель в разделе для взрослого (§17).

### 18.4 Сценарий показа за 1–2 минуты

1. Онбординг: на первом экране включить «Режим демонстрации», пройти шаги
   (тур по комнате можно пропустить), выбрать первую цель — около 30 с.
2. Хаб → «Начать работу»: распределить бюджет на «Потратить» и «Коплю»,
   выбрать тему «Бюджет» — около 10 с.
3. Экран работы: трек этапов → «Начать задание» — укороченный урок:
   ситуация, карточка, тест, событие (трата «нужно» или «хочу» из бюджета
   работы), следующий этап с мини-игрой, заключение и награда: монеты, опыт,
   новый уровень и новый облик питомца (без ошибок — ещё звезда и бонус) —
   около 40 с. Урок пройден — смена закончена, итоги на хабе: план и факт,
   выплата в кошелёк и банк.
4. Кнопка Аркады на хабе — по очереди «Викторина» (3 вопроса), «Свайпы»
   (3 карточки), «5 букв» (1 слово с подсказкой) — около 40 с.

Отключаемы; критическая информация не передаётся только звуком.

## 30. Не закрыто в этой версии

Ожидается в следующем документе: полный контент уроков по веткам; материалы презентации; пакет сопроводительной документации; порядок сдачи решения.

Отступления от ТЗ Департамента и открытые пункты — зафиксированы, а не решены молча:

1. **Визуальные комбинации питомца (§4.3, §20).** 7 вместо 9: для мишки нет арта и товаров-скинов вариантов 1–2 (отложено до появления арта); из-за этого мишка не получает скин на уровнях 2–3.
2. **Сравнение плана с фактом (§7.4).** В итогах есть план и факт по направлениям, но нет колонки «разница» и комментария питомца.
3. **Состояния питомца и подсказка о еде (§6.4, §8.1).** 2 визуальных состояния вместо 4; отдельной подсказки на главном экране «питомец голоден — купи еду» нет (ограничение «еда только голодному» реализовано).
4. **Раздел для взрослого (§17.2).** Не показывается число завершённых смен.
5. **ИИ-помощник (§16.1).** Работает на заглушке; локальная модель и датасет — следующий этап.
6. **Товары «облако» и «уют» (§12.2).** Эффекты рассчитываются, товаров в каталоге нет.
7. **Барьер раздела для взрослого (§17.1).** PIN вместо арифметического примера — согласованное отступление (пример используется для восстановления PIN).
8. **Активация демо-режима (§18.3).** По решению команды (28.09) демо включается не только в разделе для взрослого, но и переключателем на первом экране онбординга — чтобы показ за 1–2 минуты начинался с онбординга и без PIN. Ускорения демо (укороченные урок и раунды Аркады, досрочное завершение смены с полной выплатой, уровень за каждый урок, §18.2) действуют только в демо-профиле.
9. **Распределение «надо / хочу / коплю» (§7.3, §19 п. 5).** По решению команды (27.09) на планировании только «Потратить» и «Коплю»; «надо» и «хочу» видны в факте трат событий урока, в карточке «Бюджет работы» и в итогах, но не планируются. Риск для приёмки по §19 п. 5 — при необходимости вернуть поле «Надо/Хочу» внутри «Потратить».
10. **Доступность тренажёров (§10.2).** Ранее — только полностью пройденные темы, затем — тема текущего приключения; по решению команды (28.09) Аркада — на хабе: любая мини-игра по любой теме, в любой момент, в том числе до прохождения уроков темы; на смену не влияет. Вопросы берутся из уроков выбранной темы.
11. **Экран ИИ-помощника (§16).** По решению команды (27.09) вкладка ИИ-помощника временно заменена вкладкой «Копилка»; экран, списание энергии и история остались в коде, но из интерфейса сейчас недоступны. Для приёмки по §16 вкладку нужно вернуть (одна строка в `(tabs)/_layout.tsx` и `constants/mainTabs.ts`).
12. **Контент уроков из этапов (§9.1).** 16 уроков переведены в этапы механически (28.09): прежние карточки и вопросы + новые ситуации, события и заключения, по 3 этапа и одному событию в уроке. Команда присылает откорректированные уроки — контент будет заменён. Прежнее решение об «одной пачке» вопросов викторины и теста снято: теперь это отдельные действия этапа.

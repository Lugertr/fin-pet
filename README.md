# Финни

Детская обучающая игра-тамагочи по финансовой грамотности для детей 7–11 лет.
Конкурсный прототип для хакатона Департамента финансов города Москвы. Полное
техническое задание — `finni_tz_final.md`; правила и границы разработки —
`CLAUDE.md`.

Приложение полностью офлайн: без аккаунтов, без персональных данных, без
рекламы и покупок за реальные деньги. Профиль — это имя и внешний вид питомца.

## Стек

- **Клиент:** React Native (Expo SDK 57), TypeScript (строгий режим), Expo
  Router, Zustand. Стили — `StyleSheet` в файлах `*.styles.ts` поверх токенов
  темы (`src/theme`, светлая/тёмная тема); графика — `react-native-svg`,
  анимации интерфейса — `react-native-reanimated`, анимации питомца — Lottie
  (`lottie-react-native`, Apache-2.0; в вебе — `@lottiefiles/dotlottie-react`,
  MIT, WASM-рендер берётся из бандла, без CDN). Шрифт — Manrope (OFL-1.1, файлы
  из `@expo-google-fonts/manrope`, MIT; загружаются `expo-font` из бандла):
  `Text`/`TextInput` импортируются из `@/components/ui/Text` — обёртка
  подставляет файл Manrope по `fontWeight` стиля (прямой импорт из
  `react-native` запрещён правилом ESLint). Пакет NativeWind установлен, но в
  коде не используется.
- **Локальное хранилище:** SQLite (`expo-sqlite`, версионируемые миграции в
  `src/data/local/migrations`) — источник истины для профиля, питомца,
  смен, журнала событий, накоплений, прогресса уроков (по узлам — с
  какого места продолжить) и опыта игрока; Zustand + AsyncStorage — для
  магазина, подарков, достижений и истории чата с ИИ-помощником. Прогресс
  уроков из AsyncStorage (до миграции v9) переносится в SQLite при первом
  запуске. PIN раздела для взрослого — в `expo-secure-store`.
- **Сервер:** FastAPI (Python 3.11+) — минимальный каркас-заглушка под
  будущую локальную ИИ-модель (`server/`). Приложение к серверу не
  обращается; каркас существует только как задел.
- **Контент:** JSON-файлы в `content/` (ветки и уроки с событиями,
  товары, карточки свайпов Аркады, достижения, ответы ИИ-заглушки,
  словарь игры, подсказки «?» к экранам, список
  документов, флаги функций) — отделены от
  кода и UI.

## Запуск

### Требования

- Node.js 20+ и npm
- Android Studio с эмулятором, либо физическое Android-устройство с
  [Expo Go](https://expo.dev/go) — целевая платформа проекта Android

### Клиент

```bash
npm install
npx expo start
```

В выводе команды выберите запуск на Android-эмуляторе/устройстве (либо в
вебе — `npx expo start --web` — для быстрой проверки без эмулятора).

### Веб-сборка для GitHub Pages

```bash
npm run build:docs
```

Собирает веб-версию в `docs/` с базовым путём `/fin-pet` (`experiments.baseUrl`
в `app.json` — должен совпадать с именем репозитория). Дополнительно кладёт
`docs/.nojekyll` (иначе Pages не отдаст папку `_expo/`) и `docs/404.html` —
копию `index.html`, чтобы прямые ссылки и F5 на вложенных экранах открывали
приложение. Публикация: закоммитить `docs/`, в настройках репозитория
Settings → Pages → Deploy from a branch → `master` / `/docs`.

### Сервер-заглушка ИИ-помощника (необязательно)

Клиент в нём не нуждается — вся механика ИИ-помощника работает на локальной
заглушке `StubAiAssistant`. Каркас поднимается отдельно, если нужно
проверить сам сервис:

```bash
docker compose up
```

Поднимет FastAPI на `http://localhost:8000` — `/health` и `POST /ai/ask`.

## Пользовательский путь

На каждом экране есть кнопка **«?»** — короткая подсказка простыми словами:
что здесь можно делать и как это работает (тексты — `content/screen_help.json`;
в разделе для родителей — на «вы»).

1. **Онбординг** (10 шагов): знакомство с тремя типами решений (нужное,
   желаемое, отложить), выбор питомца, его облика и имени, экран «Дом и
   смена», тур по комнате (3 шага с затемнением: деньги и энергия, куда
   нажимать, вещи комнаты и их бонусы; «Пропустить» ведёт к выбору цели),
   «Выбери первую цель» (ближайшее улучшение ноутбука, копилки или кровати) и
   стартовый капитал — 50 монет в кошелёк и 50 в накопления (§4.4), которые
   сразу копятся на эту цель.
2. **Хаб** — комната питомца (ноутбук, кровать, копилка, ковёр, окно), кнопка
   «Начать смену» (во время смены — «Продолжить смену» с оставшимся
   временем) и рядом — **Аркада**. Тап по питомцу пересчитывает энергию, по
   копилке — открывает «Копилку», по ноутбуку — смену (или её планирование).
   У подписей «Смена», «Энергия», «Банк» — бонус надетой вещи, если он есть
   (+% к зарплате смены, +⚡ к запасу, +% в банке). При первом за
   день заходе (кроме самого первого дня — в него дан стартовый капитал) хаб
   показывает окно **ежедневной награды**: монеты за день стрика, на 7-й день
   — подарок.
3. **Планирование смены** — сначала тема: смена пройдёт по её следующему
   уроку (тема с начатым уроком выбрана сразу, пройденную тему выбрать
   нельзя); у темы видна зарплата её урока. Затем зарплата — бюджет смены —
   делится на «Потратить» и «Коплю»; в каждом поле плавная заливка и «N%»
   показывают долю бюджета. Нужное и желаемое не планируются — их показывает
   факт трат в событиях урока. Кнопка «Добавить из кошелька» (свои монеты в
   бюджет смены) пока скрыта — `SHOW_WALLET_CONTRIBUTION` в
   `adventure-planning.tsx`; механика и хранение остались.
4. **Смена** — отдельный экран, открывается с хаба (хаб остаётся
   хабом): трек этапов урока, «Начать задание», бюджет смены. В шапке слева
   «назад» на хаб, справа — «?» и ✕ (закончить смену раньше). Подробности — в
   следующем разделе.
5. **Итоги** — после завершения хаб показывает экран итогов: потрачено
   меньше плана — «Супер!», сколько сэкономлено и похвала с бонусом за план;
   ровно по плану — «Точно по плану!»; больше плана — «Хорошая работа!» без
   упрёка и с подсказкой на следующий раз;
   план и факт «Потратить» (и из них — на нужное и желаемое) и «Коплю»,
   перенос в копилку, бонус за план, а если урок не закончен — с какого
   этапа он продолжится; кнопки «Домой» и «Новая смена» (сразу открывает
   планирование). Опыт и новый уровень показывает экран награды урока.
   Итоги хранятся к смене, пока окно не закрыто, — после перезапуска
   приложения хаб покажет их снова.

Остальные вкладки:

- **Уроки** — матрица компетенций по 7 темам (под ней — уроки, звёзды и
  темы), темы табами (у каждой — «X/Y» пройденных уроков), карточка модуля
  (пройдено и звёзды ★ темы) и дорожка уроков. У урока на дорожке видно
  состояние — не только цветом, но и значком и подписью: ★ «Идеально» (без
  ошибок), ✓ «Пройдено», «Начат · N/M» и значок «play» (продолжится с того же
  этапа), «Следующий» (его можно пройти сейчас, и с него начнётся смена по
  теме), замок — сначала предыдущий урок темы.
  Урок из этапов: сначала этап «Теория» — ситуация по теме и все карточки
  теории урока, затем по этапу на каждый узел из `lessons.json` — только его
  задания: тест, мини-игра или событие (выбор, который тратит или пополняет
  бюджет смены; два события подряд не бывает) → сразу заключение →
  награда. Пройденные этапы сохраняются сразу — урок продолжается с того же
  места. Контент — `content/lessons.json` (формат — в разделе «Формат урока»
  ниже), правила состава проверяет тест (`domain/lesson/LessonPlan.ts`).
  Уроки открываются с вкладки по порядку внутри темы (первый, начатый,
  следующий после пройденного) и проходятся целиком; в смене тот же урок идёт
  по этапам, каждый этап стоит энергии, события тратят бюджет смены.
  Пройденный урок открывается обзором — перечитать карточки и перепройти
  тесты и игры; в демо-режиме открывается любой урок, в укороченном виде.
  **Награда за урок** (`domain/lesson/lessonRewards.ts`, начисляет
  `useLessonsStore.finishLesson`): первое прохождение — опыт; впервые без
  ошибок во всех тестах и играх урока (сразу или при перепрохождении) —
  звезда ★; повторы — без награды (§9). Монет за урок нет: урок оплачивается
  зарплатой смены (см. «Экономика урока»).
  **Подсказки** в свайпах и «5 букв» платные (цена — у кнопки подсказки,
  по умолчанию 5 C): в смене — из бюджета смены как «Хочу», вне смены — из
  кошелька (в истории — «Подсказка в игре»). Не хватает — подсказка не
  открывается, с объяснением. Повтор пройденного (обзор урока или этап с
  трека смены) — бесплатная тренировка: подсказки даром, ошибки не стоят
  энергии. В «5 буквах» подсказок две, каждая один раз
  на слово и по той же цене: описание слова и «Открыть букву» (первая ещё
  не отгаданная буква — текстом и бледно в её клетке). Подсказки Аркады
  бесплатные.
- **Копилка** (банк) — накопления и цель: копить можно только на улучшения
  ноутбука, копилки и кровати. Выбор цели — теми же карточками, что в
  онбординге. В шапке — всего монет; ниже карточка главной цели с прогрессом
  и кнопкой «Дополнить из хотений» и две «корзины»: «Хочу» (кошелёк, его
  тратит магазин — кнопка «В магазин») и «Коплю» (банк, копится на цель;
  ссылка «Снять» возвращает монеты в кошелёк в любой момент).
- **ИИ-помощник** — пока скрыт из нижней панели (на его месте «Копилка»);
  экран и логика остались: вопрос стоит 5 энергии, ответ даёт локальная
  заглушка со ссылкой на урок, историю можно очистить.
- **Магазин** — мебель и декор с настоящими картинками вещей. Покупка при
  нехватке монет блокируется с объяснением (§12.3). Еда из магазина скрыта
  (`FOOD_IN_SHOP` в `lib/utils/itemCategories.ts`; энергию в смене
  пополняет кофе), механика еды осталась.
  Мебель и декор дорогие (750–2250 C): улучшение не купить на деньги даже
  одной идеальной смены — на него копят в «Банке» (выбрав цель).
  Скинов в магазине нет: облик питомца приходит только с новым уровнем, скины
  не продаются и не выпадают в событиях и подарках.
  Еда (если её вернуть) — вынужденная мера: купить и съесть её можно, только
  когда питомец голоден (энергия < 30), и стоит она не меньше 10 монет за
  1⚡ — так «еда → Аркада» не приносит выгоды.
- **Прогресс** — уровень и облик питомца, последние достижения (экран «все
  достижения» с кнопкой «Забрать» награду), статистика (уроки, принятые
  решения в событиях, дни с Финни) и история операций с монетами; меню:
  **Настройки** (звуки, вибрация, уведомления, тема — сохраняются),
  **Родителям** (PIN), **Словарь** (слова игры простыми словами, поиск) и
  **Документы** (PDF; пока список пуст).

**Валюта** — монеты: на экране сумма всегда пишется как «80 C»
(`formatPrice`/`CoinAmount`), скринридер читает её словом («80 монет»).
Шапка: лого, кошелёк «80 C» с декоративной полоской цветов «надо / хочу /
коплю», энергия и профиль. Денег два контура, энергия общая:

- **Хаб** — кошелёк и «Банк». Кошелёк пополняют итоги смены, Аркада,
  стрик, подарки, достижения и уровни; тратится он в магазине и на подсказки
  вне смены. «Банк» — накопления на цель
  (предмет из магазина) с небольшим бонусом за новые деньги: возврат ранее
  снятого бонуса не даёт.
- **Бюджет смены** — свои деньги смены: зарплата за урок (price урока ×
  надбавка предметов; урок уже начат — только за оставшиеся этапы) и
  пополнения в событиях урока; тратят его события урока, подсказки и кофе.
  При завершении «коплю» уходит в банк, остаток — в кошелёк. Магазин и банк
  бюджет смены не трогают.

## Игровой цикл: «Смена»

Планирование бюджета и урок объединены в один цикл — смену (в коде —
adventure: `src/domain/adventure/`, `src/lib/stores/adventureStore.ts`).
Одна смена — один урок (следующий непройденный урок выбранной темы).

1. **Планирование** — см. путь выше. Зарплата урока становится бюджетом
   смены, урок смены фиксируется.
2. **Смена** — до 24 реальных часов (тикают и при закрытом приложении).
   - **Экран** (макет «Работа»): сцена с питомцем, плашка «Смена: 2 из 5» и
     трек этапов урока: первый — «Теория» (книга), дальше этапы заданий,
     в конце — флажок финиша (только отметка, не кнопка); пройденные — с
     галочкой, текущий — цветной, будущие — серые. Время до конца смены и
     «Читать теорию · −10⚡» / «Начать задание · −10⚡» (цена этапа в
     энергии; «Теория» стоит как обычный этап) — один этап урока с того же
     места; не хватает энергии — этап не начать, окно объясняет: подожди,
     пока энергия восстановится, или купи кофе. Энергия списывается, когда
     этап пройден. Этап:
     этап пройден — экран «Этап N из M пройден» и назад к смене, трек
     продвинулся. После последнего задания заключение идёт сразу (без
     «Этап пройден» и возврата к смене), затем награда урока с кнопкой «К
     итогам смены» — она ведёт прямо на хаб, где итоги; смена закрыта.
     Экран урока в стеке всегда один; если смена закончилась не на нём
     (время вышло), урок не продолжается «вне смены» — окно объясняет и
     возвращает на хаб.
     Пройденный этап на треке открывается, чтобы перечитать карточки и
     перепройти тест или игру — это бесплатная тренировка (ошибки не стоят
     энергии, подсказки бесплатные). Ниже — «Бюджет смены»: корзины «Нужно» и
     «Хочу» (факт трат) и «Коплю» (отложено из плана), тап — окно «План».
   - **Кофе** — квадратная кнопка «Выпить кофе» в левом верхнем углу сцены
     (чашка, цена и +⚡ в чипах; после покупки — «Кофе выпит»): один раз за
     смену, из бюджета смены (трата на «Хочу»), прибавляет энергию (по
     умолчанию 30 C, +10⚡). Открывается после первого этапа этой смены
     (до него на кнопке замок и «после 1-го этапа»): иначе «начал смену →
     кофе → сразу закончил» давало бы энергию даром. Когда энергия полная,
     кофе не продаётся — монеты не уходят впустую.
   - **События** — внутри урока, окном по макету: плашка «Событие», иконка,
     текст, варианты и внизу — как главный вариант ляжет на план смены.
     Выбор тратит (на нужное или желаемое) или пополняет бюджет смены.
     Вариант может стоить энергии вместо денег («30⚡» у кнопки: например,
     пойти пешком вместо платного автобуса). Вариант, на который не хватает
     бюджета или энергии, недоступен и подписан («Не хватает 5 C», «Не хватает
     энергии: нужно 30⚡»); если недоступно всё — окно подсказывает выйти и
     подождать энергию или выпить кофе. По времени событий нет.
   - **Ошибка** в тесте или игре урока смены стоит 5 энергии (единственное
     исключение из правила «ошибка не наказывается», §9).
3. **Завершение и итоги** — урок пройден — смена заканчивается сама с полной
   наградой. Не успел за 24 часа — смена заканчивается сама, а урок
   продолжится в следующую смену с того же места. ✕ заканчивает смену раньше
   (с подтверждением). Смена платит только за этапы, пройденные в ней: урок
   уже начат (в прошлой смене или на вкладке «Уроки») — зарплата только за
   оставшиеся этапы, а при досрочном завершении выплачивается доля этапов
   этой смены из оставшихся (2 из 4 — половина остатка бюджета и «коплю»)
   без бонуса банка. Так «начал смену и сразу закончил» ничего не приносит, и
   за урок по всем сменам — не больше его зарплаты. Урок смены убрали из
   `lessons.json` — зарплата не начисляется (свои монеты возвращаются). Итоги —
   полноэкранным окном на хабе: план и факт «Потратить» (с разбивкой на нужное
   и желаемое), бонус за план (в бюджет), выплата («коплю» — в банк,
   остальное — в кошелёк). Опыта смена не даёт — его дают уроки.
   Завершение смены и выплата (смена, банк, кошелёк, итоги) записываются
   одной транзакцией SQLite (`data/local/transaction.ts`): сбой посередине не
   теряет монеты и не платит дважды — смена просто остаётся активной.

**Аркада** — на хабе, кнопка рядом с «Начать смену»: любая мини-игра по
любой теме (по умолчанию — тема текущей смены): «Викторина» (до 10 вопросов из
уроков темы), «Свайпы» (до 5 ситуаций) или «5 букв» (до 3 слов темы). Игра —
10⚡, +2 C за верный ответ, можно повторять сколько угодно; на смену не
влияет. У каждой мини-игры своя подсказка «?» — как в неё играть.

Система уровней игрока (`src/domain/player/PlayerLevel.ts`) заменяет собой
стадии роста питомца. Опыт дают уроки — за первое прохождение: у каждой темы
300 опыта, они делятся поровну между её уроками (3 урока — по 100), и на
каждый уровень нужно ровно 300 — пройденная целиком тема всегда даёт новый
уровень (в демо-режиме новый уровень даёт каждый урок). Повышение уровня
показывает экран награды урока: звание, монеты и на уровнях 2 и 3 — облик
питомца, которого ещё нет (при создании выбирается любой из трёх, остальные
два приходят здесь; цветной надевается сам). Уровень никогда не понижается:
опыт, накопленный по прежней шкале (порог 250 × уровень), миграция v11
пересчитала с тем же уровнем.

Темы обучения (7, для 7–11 лет): обязательные по ТЗ — **Бюджет**
(планирование бюджета), **Сбережения**, **Покупки** (платежи и покупки);
дополнительные — **Безопасность**, **Долги**, **Заработок**, **Цены**.

## Демо-режим

Показывает весь функционал — от онбординга до повышения уровня — за 1–2
минуты (§18 ТЗ). Все ускорения действуют только в демо-профиле:

- любой урок открывается сразу и проходится в укороченном виде: первые два
  этапа, по одной карточке и по два вопроса теста; мини-игры и события —
  целиком;
- раунды Аркады короткие: 3 вопроса, 3 карточки, 1 слово;
- смену можно закончить ✕ в любой момент с полной выплатой, а каждый
  пройденный урок — новый уровень (на уровнях 2 и 3 — новый облик питомца).

**Как включить.** На первом экране онбординга — переключатель **«Режим
демонстрации»**. Для уже созданного профиля — Прогресс → **Родителям** →
PIN → переключатель «Демо-режим» (профиль вернётся к исходному состоянию).
**«Начать демо заново»** там же удаляет демо-профиль и открывает онбординг с
уже включённым режимом.

**Сценарий показа:**

1. Онбординг: на первом экране включить «Режим демонстрации», пройти шаги
   (тур по комнате можно пропустить), выбрать первую цель — около 30 с.
2. Хаб → «Начать смену»: распределить бюджет на «Потратить» и «Коплю»,
   выбрать тему «Бюджет» — около 10 с.
3. Экран смены: трек этапов → «Начать задание» — первый этап укороченного
   урока: ситуация, карточка, тест, событие (трата «нужно» или «хочу» из
   бюджета смены) → «Этап 1 из 3 пройден» → «К смене», трек продвинулся.
   Ещё раз «Начать задание» — второй этап с мини-игрой; третий раз —
   заключение и награда: монеты, опыт, новый уровень и новый облик питомца
   (без ошибок — ещё звезда и бонус) — около 50 с. Урок пройден — смена
   закончена, итоги на хабе: похвала за план, выплата в кошелёк и банк.
4. Кнопка Аркады на хабе — по очереди «Викторина» (3 вопроса), «Свайпы»
   (3 карточки), «5 букв» (1 слово с подсказкой) — около 40 с.

### Формат урока

Урок в `content/lessons.json` — ситуация, этапы и заключение:

```jsonc
{
  "id": 7, "branch_id": 3, "order_index": 1, "title": "Зачем откладывать",
  "situation": { "title": "…", "text": "…" },          // начало этапа «Теория»
  "nodes": [                                            // узел = этап заданий на треке
    {
      "cards": [{ "title": "…", "text": "…", "bonusFact": "…" }], // → в этап «Теория»
      "activities": [                                   // задания этапа по порядку
        { "type": "test", "questions": [ /* вопросы */ ] },
        { "type": "minigame", "minigame_type": "quiz", "questions": [ /* … */ ] },
        { "type": "minigame", "minigame_type": "tinder_swipe", "questions": [ /* … */ ] },
        { "type": "minigame", "minigame_type": "five_letters", "word": "ВЗЛОМ" },
        { "type": "event", "pool": [ /* из пула выпадает одно событие */ ] }
      ]
    }
  ],
  "conclusion": { "title": "…", "text": "…" }          // финальный этап трека
}
```

- Вопрос: `id` (уникален во всём контенте), `question_text`, `options`,
  `correct_answer` (одна из `options`), `question_type` (`test` или
  `minigame`); у свайпов — ещё `explanation` и `hint`. В тексте `**термин**`
  выделяется.
- Свайп — вопрос «да / нет» (текст заканчивается «?»), `options` — ровно
  `[ответ «нет», ответ «да»]`: в игре влево / ✗ — «нет», вправо / ✓ — «да»,
  стороны постоянные и не выдают верный ответ. То же — у карточек
  `content/arcade_swipe_cards.json`.
- Событие: `id`, `title`, `description`, `icon`, 2–3 варианта `{ id, label,
  category, coinAmount }`: `coinAmount` — целые монеты бюджета смены
  (минус — трата, плюс — пополнение), трата — с корзиной `mandatory` (нужное)
  или `optional` (желаемое), хотя бы один вариант бесплатный. Первый вариант
  — главный: его кнопка выделена, а внизу окна показано, как он ляжет на план
  смены (бюджет «было → станет», факт «Нужно»/«Хочу» и полоска «Потратить»).
- `icon` события: эмодзи; `"question"` или `"reward"` — персонаж (питомец
  ребёнка в текущем облике, как в карточках урока); или ключ картинки из
  `src/constants/eventIcons.ts` (сейчас `laptop`, `piggybank`, `bed`,
  `window`, `carpet`). Новая картинка — файл в `assets/images/` и строка в
  `EVENT_ICON_IMAGES` (React Native подключает картинки только статически);
  опечатку в ключе ловит `npm test`.
- Правила состава: в первом этапе — тест или мини-игра и событие; в каждом
  этапе есть карточки и действия; двух событий подряд нет. Нарушения
  показывает `npm test` (`LessonPlan.test.ts`).
- Прогресс урока хранится по номерам «этап.действие» вместе с отпечатком
  структуры (типы действий по этапам). Правка текстов прогресс не трогает; если
  поменялся состав этапов, начатый урок после обновления продолжится с начала
  (пройденные уроки, звёзды, монеты и опыт сохраняются).

#### Экономика урока

Поля необязательные, без них — значения по умолчанию
(`src/domain/lesson/lessonEconomy.ts`). Все числа — целые ≥ 0, проверяет
`npm test`.

| Поле | Где | По умолчанию | Смысл |
|---|---|---|---|
| `price` | урок | 100 | Зарплата смены = price × (1 + надбавка предметов %) |
| `nodeEnergyCost` | урок | 10 | Энергия за каждый этап урока в смене |
| `energyCost` | этап (`nodes[i]`) | = `nodeEnergyCost` | Своя цена этапа |
| `coffee` | урок | `{ "price": 30, "energy": 10 }` | Кофе: раз за смену, из бюджета смены |
| `hintPrice` | мини-игра | 5 | Цена подсказки (0 — бесплатно); в «5 буквах» — и описания, и «Открыть букву» |
| `energyCost` | вариант события | — | Энергия вместо денег (−N⚡ у кнопки) |

Пример урока, в котором есть все виды этапов, действий, иконок событий и
поля экономики, — `content/lessons.example.json`. Он же добавлен в игру:
тема «Бюджет», 1-й урок «Неделя на карманные» (id 900, вопросы 99001–99006;
тест `lessonEconomy.test.ts` проверяет, что копия в `lessons.json` совпадает
с файлом примера и проходит ту же проверку, что и остальные уроки).
Остальные уроки пока без полей экономики — работают значения по умолчанию.

Репозитории и контент спрятаны за доменными интерфейсами
(`src/domain/repositories/*`, `ContentRepository`) — источник данных
(сейчас: SQLite + локальные JSON) можно заменить на серверный без изменения
экранов и сторов.

## Анимации питомца

Питомец всегда нарисован статичным SVG своего состояния (`idle` или
`sleeping` при энергии ≤ 20). Нажатие на питомца в хабе и в онбординге
(выбор питомца, настройка облика) проигрывает анимацию один раз: бодрый —
радость, уставший — сонливость; затем снова SVG. Исходные анимации длинные
(до 32 с), поэтому играется отрывок 3–5 с, который заканчивается кадром,
совпадающим с первым, — возврат к SVG проходит без скачка.

- **Исходники** — dotLottie-файлы рядом с SVG:
  `assets/images/pets/<вид>/<вид>_happy.lottie` и `<вид>_sleepy.lottie`
  (вид — `robot`, `bear`, `cat`). После замены или добавления файла:

  ```bash
  npm run pets:animations
  ```

  Скрипт `scripts/build-pet-animations.js` распаковывает JSON в
  `assets/animations/pets/`, заменяет текстовые «Z» векторными буквами
  (шрифтов в приложении нет) и пересчитывает палитры скинов.
- **Скины** — перекраска той же анимации. Пары «цвет классического облика →
  цвет скина» скрипт берёт из SVG `v0` и `v1`/`v2`
  (`assets/images/pets/<вид>/v<N>/`): элементы сопоставляются по геометрии, а
  если SVG переэкспортированы (другое округление координат) — по первой точке
  (до 3 px); пара засчитывается минимум с двух совпадений. Оттенки, которых в
  SVG нет, пересчитываются от ближайшего цвета, всё пишется в
  `assets/animations/pets/palettes.json`. Скин со своим рисунком (сопоставилось
  меньше 75% элементов) палитры не получает — по нажатию на него анимация не
  играет, остаётся SVG.
  Цвета подставляются в рантайме (`src/domain/pet/petAnimation.ts`), поэтому в
  бандле одна анимация на состояние, а не копия на каждый скин. Свотч облика в
  `content/items.json` должен быть одним из цветов его анимации — это
  проверяет тест.
- **Отрывок и рамка** — в классах видов (`src/domain/pet/species/*Pet.ts`):
  `endFrame` — до какого кадра играть, `body` — где в кадре анимации лежит
  SVG того же состояния (по ней анимация совмещается со спрайтом). После
  замены анимации их стоит перепроверить.
- **Мишка:** `bear_happy` — «сборка» статичного рисунка из деталей, по
  нажатию играется целиком (0,8 с); спящей анимации пока нет — нажатие на
  уставшего мишку ничего не проигрывает.

# Финни

Детская обучающая игра-тамагочи по финансовой грамотности для детей 7–11 лет.
Конкурсный прототип для хакатона Департамента финансов города Москвы. Полное
техническое задание — `finni_tz_final.md`; правила и границы разработки —
`CLAUDE.md`.

Приложение полностью офлайн: без аккаунтов, без персональных данных, без
рекламы и покупок за реальные деньги. Профиль — это имя и внешний вид питомца.

## Стек

- **Клиент:** React Native (Expo SDK 57), TypeScript (строгий режим), Expo
  Router, Zustand. Стили — `StyleSheet` в файлах `*.styles.ts` поверх токенов
  темы (`src/theme`, светлая/тёмная тема); графика — `react-native-svg`,
  анимации интерфейса — `react-native-reanimated`, анимации питомца — Lottie
  (`lottie-react-native`, Apache-2.0; в вебе — `@lottiefiles/dotlottie-react`,
  MIT, WASM-рендер берётся из бандла, без CDN). Пакет NativeWind установлен, но
  в коде не используется.
- **Локальное хранилище:** SQLite (`expo-sqlite`, версионируемые миграции в
  `src/data/local/migrations`) — источник истины для профиля, питомца,
  приключений, журнала событий и накоплений; Zustand + AsyncStorage — для
  прогресса уроков/уровня, магазина, подарков, достижений и истории чата с
  ИИ-помощником. PIN раздела для взрослого — в `expo-secure-store`.
- **Сервер:** FastAPI (Python 3.11+) — минимальный каркас-заглушка под
  будущую локальную ИИ-модель (`server/`). Приложение к серверу не
  обращается; каркас существует только как задел.
- **Контент:** JSON-файлы в `content/` (ветки и уроки, товары, события
  приключения, карточки свайпов Аркады, достижения, ответы ИИ-заглушки,
  словарь игры, подсказки «?» к экранам, список
  документов, флаги функций) — отделены от
  кода и UI.

## Запуск

### Требования

- Node.js 20+ и npm
- Android Studio с эмулятором, либо физическое Android-устройство с
  [Expo Go](https://expo.dev/go) — целевая платформа проекта Android

### Клиент

```bash
npm install
npx expo start
```

В выводе команды выберите запуск на Android-эмуляторе/устройстве (либо в
вебе — `npx expo start --web` — для быстрой проверки без эмулятора).

### Сервер-заглушка ИИ-помощника (необязательно)

Клиент в нём не нуждается — вся механика ИИ-помощника работает на локальной
заглушке `StubAiAssistant`. Каркас поднимается отдельно, если нужно
проверить сам сервис:

```bash
docker compose up
```

Поднимет FastAPI на `http://localhost:8000` — `/health` и `POST /ai/ask`.

## Пользовательский путь

На каждом экране есть кнопка **«?»** — короткая подсказка простыми словами:
что здесь можно делать и как это работает (тексты — `content/screen_help.json`;
в разделе для родителей — на «вы»).

1. **Онбординг** (10 шагов): знакомство с тремя типами решений (нужное,
   желаемое, отложить), выбор питомца, его облика и имени, экран «Дом и
   приключения», тур по комнате (3 шага с затемнением: деньги и энергия, куда
   нажимать, вещи комнаты и их бонусы; «Пропустить» ведёт к выбору цели),
   «Выбери первую цель» (ближайшее улучшение ноутбука, копилки или кровати) и
   стартовый капитал — 50 монет в кошелёк и 50 в накопления (§4.4), которые
   сразу копятся на эту цель.
2. **Хаб** — комната питомца (ноутбук, кровать, копилка, ковёр, окно) и кнопка
   «Начать приключение» (во время приключения — «Продолжить приключение» с
   оставшимся временем). Тап по питомцу пересчитывает энергию, по копилке —
   открывает «Копилку», по ноутбуку — приключение (или его планирование). У подписей
   «Приключение», «Энергия», «Банк» — бонус надетой вещи, если он есть
   (+% монет за уроки, +⚡ к запасу, +% в банке). При первом за
   день заходе (кроме самого первого дня — в него дан стартовый капитал) хаб
   показывает окно **ежедневной награды**: монеты за день стрика, на 7-й день
   — подарок.
3. **Планирование приключения** — бюджет приключения (100 C) делится на
   «Потратить» и «Коплю»; в каждом поле плавная заливка и «N%» показывают долю
   бюджета. Затем выбирается одна из 7 тем обучения. Нужное и желаемое не
   планируются — их показывает факт трат событий.
4. **Приключение** — отдельный экран, открывается с хаба (хаб остаётся
   хабом): задания по выбранной теме, случайные события, бюджет и план. В
   шапке слева «назад» на хаб, справа рядом с монетами и энергией — «?» и ✕
   (завершить досрочно). Подробности — в следующем разделе.
5. **Итоги** — после завершения хаб показывает экран итогов: «Отличная
   работа!» (или нейтральное «Приключение завершено», если трат больше плана),
   план и факт «Потратить» (и из них — на нужное и желаемое) и «Коплю»,
   перенос в банк и в кошелёк, опыт, новый уровень; кнопки «Домой» и «Новое
   приключение» (сразу открывает планирование).

Остальные вкладки:

- **Уроки** — матрица компетенций по 7 темам, темы табами (у каждой — «X/Y»
  пройденных уроков), карточка модуля и дорожка уроков.
  Урок: карточки теории → мини-игра → тест → награда; у урока-викторины
  вопросы мини-игры и теста идут одной пачкой («Вопрос 1 из 6»), у «Свайпов» и
  «5 букв» мини-игра — отдельный шаг.
  Новые уроки проходятся только как задания приключения; пройденный урок можно
  повторить, но без награды (§9); в демо-режиме открывается любой урок.
- **Копилка** (банк) — накопления и цель: копить можно только на улучшения
  ноутбука, копилки и кровати. Выбор цели — теми же карточками, что в
  онбординге. В шапке — всего монет; ниже карточка главной цели с прогрессом
  и кнопкой «Дополнить из хотений» и две «корзины»: «Хочу» (кошелёк, его
  тратит магазин — кнопка «В магазин») и «Коплю» (банк, копится на цель;
  ссылка «Снять» возвращает монеты в кошелёк в любой момент).
- **ИИ-помощник** — пока скрыт из нижней панели (на его месте «Копилка»);
  экран и логика остались: вопрос стоит 5 энергии, ответ даёт локальная
  заглушка со ссылкой на урок, историю можно очистить.
- **Магазин** — нужное (еда, восстанавливает энергию) и желаемое (мебель,
  декор) — с настоящими картинками вещей (для еды — эмодзи). Покупка при
  нехватке монет блокируется с объяснением (§12.3).
  Мебель и декор дорогие (750–2250 C): улучшение не купить на деньги даже
  одного идеального приключения — на него копят в «Банке» (выбрав цель).
  Скинов в магазине нет: облик питомца приходит только с новым уровнем, скины
  не продаются и не выпадают в событиях и подарках.
  Еда — вынужденная мера: купить и съесть её можно, только когда питомец
  голоден (энергия < 30), и стоит она не меньше 10 монет за 1⚡ — так
  «еда → Аркада» не приносит выгоды.
- **Прогресс** — уровень и облик питомца, последние достижения (экран «все
  достижения» с кнопкой «Забрать» награду), статистика (уроки, принятые
  решения в событиях, дни с Финни) и история операций с монетами; меню:
  **Настройки** (звуки, вибрация, уведомления, тема — сохраняются),
  **Родителям** (PIN), **Словарь** (слова игры простыми словами, поиск) и
  **Документы** (PDF; пока список пуст).

**Валюта** — монеты: на экране сумма всегда пишется как «80 C»
(`formatPrice`/`CoinAmount`), скринридер читает её словом («80 монет»).
Шапка: лого, кошелёк «80 C» с декоративной полоской цветов «надо / хочу /
коплю», энергия и профиль. Денег два контура, энергия общая:

- **Хаб** — кошелёк и «Банк». Кошелёк пополняют уроки (сразу по прохождении,
  в том числе уроки-задания), Аркада, стрик, подарки, достижения, уровни и
  итоги приключений; тратится он в магазине. «Банк» — накопления на цель
  (предмет из магазина) с небольшим бонусом за новые деньги: возврат ранее
  снятого бонуса не даёт.
- **Бюджет приключения** — свои деньги приключения: 100 монет дохода плюс
  награды событий; тратят его только события. При завершении «коплю» уходит в
  банк, остаток — в кошелёк. Магазин и банк бюджет приключения не трогают.

## Игровой цикл: «Приключение»

Планирование бюджета и прохождение уроков объединены в один цикл (см.
`src/domain/adventure/`, `src/lib/stores/adventureStore.ts`):

1. **Планирование** — см. путь выше. Доход становится бюджетом приключения.
2. **Активная фаза** — 8 реальных часов (тикают и при закрытом приложении).
   - **Экран:** сцена с питомцем, полоска прогресса с оставшимся временем и
     бюджетом приключения, кнопка «Выполнить задание» (следующий урок темы) и
     рядом — вход в Аркаду (на хабе её нет), тема урока и кнопка «План»
     (модалка по центру: бюджет, потрачено / по плану, коплю). «Банка» в
     приключении нет — он только на хабе (тап по копилке). ✕ слева сверху —
     завершить приключение (с подтверждением). Досрочно — только пройденная
     доля всего: закрыто на 10% — 10% бюджета, «коплю» и опыта, без бонуса
     банка (иначе «начал и сразу закрыл» приносило бы бюджет).
   - **Задания:** пройденный урок темы ускоряет таймер на 45 минут, а монеты
     за урок сразу идут в кошелёк хаба; неверный ответ в задании стоит 5 энергии
     (единственное исключение из правила «ошибка не наказывается», §9). Если
     тема уже пройдена на 100% — заданием становится раунд Аркады по ней.
   - **Аркада** (кнопка рядом с заданием) — любая мини-игра по теме
     приключения: «Викторина» (до 10 вопросов из уроков темы), «Свайпы» (до 5
     ситуаций) или «5 букв» (до 3 слов темы). Игра — 10⚡, +2 C за верный
     ответ, можно повторять сколько угодно. Раунд приближает финиш приключения,
     но слабее урока: до 15 минут по доле верных ответов (урок — 45). У каждой
     мини-игры своя подсказка «?» — как в неё играть.
   - **Случайные события** (трата/награда из бюджета приключения, изменение
     времени) не останавливают
     прогресс, но не дают завершить приключение, пока не решены. Ритм
     (`EVENT_PACING` в `src/domain/adventure/AdventureEvent.ts`): примерно раз
     в час; при заходе на вкладку приключения — уже через 30 минут после
     предыдущего, но только если у питомца есть энергия, в бюджете
     приключения есть деньги, план трат не исчерпан и до конца больше часа. Не больше 6
     событий за приключение, без повторов; за 20 минут до конца и после него
     событий нет. Платный вариант, на который не хватает бюджета, недоступен (в
     каждом событии есть бесплатный). Предметов и скинов события не выдают.
3. **Итоги** — когда время вышло, приключение завершается само (при запуске
   приложения или на вкладке приключения); ещё не решённое событие при этом
   снимается без последствий. Итоги — и после автоматического, и после
   ручного завершения — показываются полноэкранным окном на хабе: план и факт
   «Потратить» (с разбивкой факта на нужное и желаемое), бонус за план (в бюджет), выплата остатка бюджета («коплю» — в банк,
   остальное — в кошелёк), 150 опыта, повышение уровня (на уровнях 2 и 3 —
   облик питомца, которого ещё нет: при создании выбирается любой из трёх,
   остальные два приходят здесь; цветной надевается сам).

Система уровней игрока (`src/domain/player/PlayerLevel.ts`) заменяет собой
стадии роста питомца. Опыт даёт только завершение приключения (150): уровень 2
— после 2 приключений, уровень 3 — после 5 (в демо-режиме — новый уровень за
каждое приключение). Уровень никогда не понижается.

Темы обучения (7, для 7–11 лет): обязательные по ТЗ — **Бюджет**
(планирование бюджета), **Сбережения**, **Покупки** (платежи и покупки);
дополнительные — **Безопасность**, **Долги**, **Заработок**, **Цены**.

## Демо-режим

Показывает весь функционал — от онбординга до повышения уровня — за 1–2
минуты (§18 ТЗ). Все ускорения действуют только в демо-профиле:

- любой урок открывается сразу и проходится в укороченном виде: 2 карточки
  теории, мини-игра и 2 вопроса теста;
- события приключения — при каждом заходе на его экран, через 1–2 с, не
  больше двух и по сценарию: сначала трата «надо/хочу», затем подарок;
- раунды Аркады короткие: 3 вопроса, 3 карточки, 1 слово;
- приключение завершается ✕ в любой момент с полной наградой, и каждое
  демо-приключение — новый уровень (на уровнях 2 и 3 — новый облик питомца).

**Как включить.** На первом экране онбординга — переключатель **«Режим
демонстрации»**. Для уже созданного профиля — Прогресс → **Родителям** →
PIN → переключатель «Демо-режим» (профиль вернётся к исходному состоянию).
**«Начать демо заново»** там же удаляет демо-профиль и открывает онбординг с
уже включённым режимом.

**Сценарий показа:**

1. Онбординг: на первом экране включить «Режим демонстрации», пройти шаги
   (тур по комнате можно пропустить), выбрать первую цель — около 30 с.
2. Хаб → «Начать приключение»: распределить бюджет на «Потратить» и «Коплю»,
   выбрать тему — около 10 с.
3. Экран приключения: через 1–2 с — событие «Захотелось перекусить» (выбор
   «надо» или «хочу», трата из бюджета приключения).
4. «Выполнить задание» — укороченный урок: 2 карточки теории, затем одной
   пачкой вопрос мини-игры и 2 вопроса теста, награда — около 20 с.
5. Возврат к приключению — второе событие, «Неожиданный подарок».
6. Кнопка Аркады — по очереди «Викторина» (3 вопроса), «Свайпы» (3 карточки),
   «5 букв» (1 слово с подсказкой) — около 40 с.
7. ✕ → «Завершить» — итоги на хабе: план и факт, выплата в кошелёк и банк,
   новый уровень и новый облик питомца.

## Сброс и удаление профиля

Из того же раздела «Родителям» (§17.2):

- **Сброс профиля** — экономика и игровой прогресс возвращаются к исходному
  состоянию (50 монет в кошелёк + 50 в накопления, §4.4), имя и питомец
  сохраняются.
- **Удаление профиля** — полное и необратимое удаление всех локальных
  данных (SQLite + AsyncStorage + PIN); приложение возвращается к онбордингу.

Оба действия требуют подтверждения и доступны только после барьера входа.

## Флаги функций

`content/features.json` (§26 ТЗ) — полный список подсистем и их состояние.
Рантайм-переключателями являются `ai_assistant_local`, `demo_mode` и
`adult_section`; остальные флаги документируют, какие подсистемы собраны.
`online_auth`, `content_sync_server` и `admin_panel` — сознательно не
реализованы (см. «Жёсткие ограничения» в `CLAUDE.md`: офлайн-first, без
аккаунтов и бэкенда).

## Структура проекта

```
src/app/             — экраны (Expo Router): (auth) онбординг, (tabs) вкладки,
                       (modal) планирование, урок, аркада, банк, раздел для взрослого
src/components/      — UI-компоненты по фичам (adventure, lessons, shop, shared…)
src/domain/          — доменная логика: сущности, чистые функции, интерфейсы
                       репозиториев; не зависит ни от UI, ни от хранилища
src/data/            — реализации репозиториев (SQLite, миграции) и локальный
                       контент-репозиторий поверх content/*.json
src/lib/stores/      — Zustand-сторы игровых систем (приключение, накопления,
src/lib/hooks/         питомец, магазин, уроки, подарки, достижения, ИИ-чат)
src/lib/…            — прикладная логика экранов (adventure, lessons, profile…)
src/theme/, styles/  — токены и темы, стили экранов
content/             — учебный контент и конфигурация, JSON (§25 ТЗ)
server/              — минимальный FastAPI-каркас (см. выше)
```

Репозитории и контент спрятаны за доменными интерфейсами
(`src/domain/repositories/*`, `ContentRepository`) — источник данных
(сейчас: SQLite + локальные JSON) можно заменить на серверный без изменения
экранов и сторов.

## Анимации питомца

Питомец всегда нарисован статичным SVG своего состояния (`idle` или
`sleeping` при энергии ≤ 20). Нажатие на питомца в хабе и в онбординге
(выбор питомца, настройка облика) проигрывает анимацию один раз: бодрый —
радость, уставший — сонливость; затем снова SVG. Исходные анимации длинные
(до 32 с), поэтому играется отрывок 3–5 с, который заканчивается кадром,
совпадающим с первым, — возврат к SVG проходит без скачка.

- **Исходники** — dotLottie-файлы рядом с SVG:
  `assets/images/pets/<вид>/<вид>_happy.lottie` и `<вид>_sleepy.lottie`
  (вид — `robot`, `bear`, `cat`). После замены или добавления файла:

  ```bash
  npm run pets:animations
  ```

  Скрипт `scripts/build-pet-animations.js` распаковывает JSON в
  `assets/animations/pets/`, заменяет текстовые «Z» векторными буквами
  (шрифтов в приложении нет) и пересчитывает палитры скинов.
- **Скины** — перекраска той же анимации. Пары «цвет классического облика →
  цвет скина» скрипт берёт из SVG `v0` и `v1`/`v2`
  (`assets/images/pets/<вид>/v<N>/`), оттенки, которых в SVG нет, пересчитывает
  от ближайшего цвета и пишет всё в `assets/animations/pets/palettes.json`.
  Цвета подставляются в рантайме (`src/domain/pet/petAnimation.ts`), поэтому в
  бандле одна анимация на состояние, а не копия на каждый скин. Свотч облика в
  `content/items.json` должен быть одним из цветов его анимации — это
  проверяет тест.
- **Отрывок и рамка** — в классах видов (`src/domain/pet/species/*Pet.ts`):
  `endFrame` — до какого кадра играть, `body` — где в кадре анимации лежит
  SVG того же состояния (по ней анимация совмещается со спрайтом). После
  замены анимации их стоит перепроверить.
- **Мишка:** `bear_happy` — «сборка» статичного рисунка из деталей, по
  нажатию играется целиком (0,8 с); спящей анимации пока нет — нажатие на
  уставшего мишку ничего не проигрывает.

## Тесты

Jest (`jest-expo`) — покрывает ключевые расчёты по явному списку CLAUDE.md.
Это тесты логики (доменные функции и сторы), не UI: рендер экранов ими не
проверяется.

```bash
npm test          # прогнать один раз
npm run test:watch
```

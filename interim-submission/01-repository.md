## Что нужно сделать команде до отправки ссылки

1. **Слить `new-adventure` в `master`** (или отправить ссылку на ветку). Ветка по умолчанию — `master`, а в ней старая версия (коммит `2a7e401`, до перехода на «смены»). Кто откроет репозиторий по ссылке, увидит именно её.
2. **Закоммитить или отложить текущие правки.** В рабочей копии не закоммичены изменения магазина, хранилища, копилки и шага 4 онбординга. В репозитории их нет.
3. **Выбрать один официальный репозиторий.** Рядом с проектом лежит клон `ssh://ssh.sourcecraft.dev/pm-x-fe-team/finni.git` (папка `C:\hakaton\frontend\res`, ветка `main`, сайт из `docs/`, базовый путь `/finni`). Это отдельная копия со своей историей. Экспертам нужна одна ссылка, и README должен описывать именно её.
4. **Решить судьбу служебных файлов.** `CLAUDE.md`, `AGENTS.md` и `.claude/settings.json` содержат инструкции для ИИ-ассистента разработки. Секретов в них нет, но экспертам они не нужны.

## Если потребуется закрытый репозиторий

Порядок доступа к закрытому репозиторию подтверждает организатор. На GitHub это делается через Settings → Collaborators, где экспертам по их логинам выдаётся роль Read. Логины экспертов нужно запросить у организатора (вопрос 7.13).

## Проверка на секреты

Проверены все отслеживаемые файлы, кроме собранного бандла `docs/` и `package-lock.json`:

- паролей, токенов, API-ключей и закрытых ключей нет;
- файлов `.env`, `*.jks`, `*.keystore`, `*.p12`, `*.pem` нет ни в индексе, ни в истории;
- `.gitignore` исключает `*.jks`, `*.p8`, `*.p12`, `*.key`, `*.pem`, `.env*.local` и генерируемые папки `/android`, `/ios`.

Ключ подписи release-APK хранить вне репозитория (см. `03-apk-prototype-video.md`).

## Что в репозитории

```
src/            исходный код приложения (экраны, компоненты, доменная логика, хранение)
content/        учебный контент и каталоги в JSON (уроки по темам, товары, словарь, подсказки)
assets/         изображения, анимации питомцев, звуки
scripts/        сборка анимаций питомцев, проверка экономики уроков
docs/           собранная веб-версия для GitHub Pages (генерируется `npm run build:docs`)
README.md       описание, запуск, демо-режим, формат урока, тесты
finni_tz_final.md  внутреннее ТЗ команды (сведённая версия; частично устарело — см. team-notes.md)
```

Серверной части в репозитории нет. `docker-compose.yml` ссылается на папку `server/`, которую удалили 27.09.2026 в коммите `c2f4a3c`. Этот хвост надо либо убрать, либо восстановить каркас (см. `07-questions.md`, вопрос 7.12, и `team-notes.md`).

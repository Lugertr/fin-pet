Контекст

Проект: Финни — детская обучающая игра-тамагочи по финансовой грамотности для детей 7–11 лет. Android, конкурсный прототип для хакатона Департамента финансов города Москвы.

Стек:

Клиент: React Native (Expo), локальное хранение — SQLite (expo-sqlite)
Сервер: FastAPI (Python 3.11+) — только для локальной ИИ-модели питомца; сейчас ИИ не реализуем, делаем заглушку

Репозиторий уже инициализирован. Твоя задача — доработать существующий код, а не создавать проект с нуля.

Полное техническое задание — в приложенном файле finni_tz_final.md. Считай его источником истины. Ссылки на разделы ниже (§N) — это разделы ТЗ.

Жёсткие ограничения (нарушать нельзя)
Офлайн-first. Весь игровой цикл работает без сети. Источник истины — локальная SQLite. Сервер не участвует ни в одной обязательной механике.
Никакой авторизации, никаких персональных данных. Профиль = имя питомца + внешний вид. Ни email, ни телефона, ни аккаунта (§4, §22).
Отрицательный баланс невозможен. Покупка при нехватке средств блокируется с объяснением и вариантами действий (§12.3).
Прогресс не теряется. Сохранение после каждого действия; полное восстановление после перезапуска (§4.5).
Ошибка ребёнка не наказывается. Нет смерти/болезни/травмы питомца, нет обнуления прогресса, стадия роста не понижается (§8).
Учебный контент отделён от UI — JSON-файлы в content/, не зашитые в компоненты (§25).
Ничего запрещённого границами проекта: реклама, платные подписки, встроенные покупки, реальные деньги, внешние ссылки для детей (§22, §27).
Доступность: тап-зоны ≥48×48 dp, основной текст ≥16 sp, цвет не единственный носитель смысла (§23).
Производительность: старт до главного экрана ≤5 с, отклик на действие ≤1 с (§24).
Все денежные и энергетические расчёты — целочисленные там, где это деньги; никаких плавающих остатков на балансе.

Тесты

Покрой автотестами ключевую логику расчётов (§ ТЗ требует этого явно):

план бюджета: сумма распределения ≤ доступный бюджет, остаток
покупка: проверка достаточности средств, списание, запрет отрицательного баланса
накопления: перевод, снятие, прогресс к цели, невозможность уйти в минус
план vs факт за период
рост стадии по «успешным периодам» (§8.2)
восстановление энергии по времени (§6.3)
Правила работы
Не выдумывай требования. Если чего-то нет в ТЗ и нет в коде — спроси, не достраивай по своему усмотрению.
Не ставь заглушки там, где ТЗ требует работающей механики. Заглушка разрешена ровно одна — ответ ИИ.
Не добавляй зависимости без необходимости; каждую новую библиотеку обоснуй (нужен перечень лицензий в сдаче).
Не используй localStorage/sessionStorage. Хранение — SQLite; эфемерное состояние — React state.
Держи миграции БД версионируемыми: схема будет меняться между спринтами.
Коммить по этапам, осмысленными сообщениями; секретов и ключей в репозитории быть не должно.
Веди README.md в актуальном состоянии (стек, запуск, демо-режим, сброс профиля) — он входит в конкурсную сдачу.
